# คำสั่งปฏิบัติงานสอบเทียบ

## ขอบเขตที่ผู้ใช้ระบุ

เพิ่มหน้าคำสั่งก่อนเลือกโรงพยาบาล แต่ละคำสั่งมีหลายโรงพยาบาล รายการเครื่องมือของโรงพยาบาลที่จะสอบเทียบ ทีมผู้ปฏิบัติงานที่เลือกจาก user ในระบบ และไฟล์ PDF คำสั่ง เพิ่มแท็บ “คำสั่ง” ในหน้าจัดการระบบ โดย admin และ technician (จนท.สอบเทียบ) เพิ่ม แก้ไข และจัดการได้

## รูปแบบการใช้งาน

- เพิ่มแท็บ “คำสั่ง” ที่ `/admin?tab=orders` เคียงข้างแท็บจัดการข้อมูลเดิม ทั้ง admin และ technician ใช้งานได้
- หน้ารายการแสดงเลขที่คำสั่ง ชื่อเรื่อง ช่วงวันที่ จำนวน รพ. จำนวนเครื่องมือ และทีม พร้อมค้นหา เพิ่ม และแก้ไข
- ฟอร์มเลือกหลายโรงพยาบาลจากข้อมูลเดิม แล้วเลือกเครื่องมือรายชิ้นจากทะเบียนของแต่ละโรงพยาบาล แสดงชื่อเครื่องมือ AmedNo รุ่น และหมายเลขเครื่องเพื่อแยกเครื่องชื่อซ้ำ
- ทีมเลือกได้หลายคนจากบัญชีที่ยังใช้งาน แสดงชื่อและ username ไม่เพิ่มบัญชีใหม่ผ่านฟอร์มนี้
- แนบ PDF ได้หลายไฟล์ แสดงชื่อไฟล์ วันที่อัปโหลด เปิดดู ดาวน์โหลด และลบไฟล์แนบได้
- เพิ่มหน้า `/orders` สำหรับเลือกคำสั่งก่อนเข้าสู่พื้นที่โรงพยาบาล เมื่อเลือกคำสั่งแสดงเฉพาะโรงพยาบาลและเครื่องมือในคำสั่ง มีทางกลับไปเลือกคำสั่งอื่น
- แสดงเลขที่คำสั่งปัจจุบันในพื้นที่ทำงาน เมื่อเปลี่ยนคำสั่งล้างการเลือกโรงพยาบาลที่ไม่อยู่ในคำสั่งใหม่
- หน้าจัดการระบบและโปรไฟล์เข้าได้แม้ยังไม่เลือกคำสั่ง เพื่อให้สร้างคำสั่งแรกได้

## ข้อมูลและความสัมพันธ์

เพิ่ม WorkOrder เก็บเลขที่คำสั่งไม่ซ้ำ ชื่อเรื่อง วันที่เริ่มและสิ้นสุด หมายเหตุ โรงพยาบาล เครื่องมือที่เลือกแยกตามโรงพยาบาล user IDs ของทีม ผู้สร้าง ผู้แก้ไข และเวลาแก้ไข อ้างอิงเครื่องมือด้วย ID ของทะเบียนและเก็บข้อมูลแสดงผลที่จำเป็น

เพิ่ม WorkOrderDocument เก็บข้อมูล PDF แยกจากรายละเอียดคำสั่ง ตามแนวทางไฟล์ใบรับรองที่มีอยู่แล้วใน MongoDB เพื่อไม่ส่งเนื้อหาไฟล์ไปกับรายการคำสั่ง จำกัด 8 MB ต่อไฟล์ ตรวจชนิด ขนาด และลายเซ็น PDF ก่อนบันทึก

งานสอบเทียบใหม่เก็บ workOrderId และตรวจโรงพยาบาลกับเครื่องมือให้ตรงคำสั่งที่เลือก ประวัติเดิมที่ไม่มีคำสั่งยังเปิดดูได้ ไม่โยกประวัติย้อนหลังอัตโนมัติ เครื่องมือเดียวกันอยู่ในหลายคำสั่งได้สำหรับการออกปฏิบัติงานคนละรอบ

## สิทธิ์และข้อเสนอเริ่มต้น

admin และ technician จัดการทุกคำสั่งและไฟล์แนบได้ บังคับสิทธิ์ใน API ด้วย ไม่อาศัยการซ่อนปุ่มอย่างเดียว รายชื่อสำหรับเลือกทีมส่งเฉพาะข้อมูลบัญชีที่จำเป็น ไม่ส่งรหัสผ่านหรือข้อมูลส่วนตัวอื่น

ข้อเสนอสำหรับสิทธิ์อ่าน: ผู้ใช้ภายในที่มีสิทธิ์เดิมอ่านคำสั่งได้ การอยู่ในทีมเป็นข้อมูลการมอบหมายงาน ไม่เปลี่ยนสิทธิ์ของบัญชี ผู้ใช้โรงพยาบาลเห็นเฉพาะส่วนของโรงพยาบาลตนและยังคงข้อจำกัดเดิม ไม่เปิดเผยโรงพยาบาลอื่นหรือ PDF คำสั่งที่อาจรวมข้อมูลหลายโรงพยาบาล

ข้อเสนอสำหรับลบคำสั่ง: ลบได้เมื่อไม่มีงานสอบเทียบอ้างอิง ถ้ามีงานอ้างอิงให้ปฏิเสธพร้อมคำอธิบาย ไม่ลบงานหรือประวัติตามคำสั่ง การแก้ไขห้ามนำโรงพยาบาลหรือเครื่องมือที่มีงานในคำสั่งออกจนความสัมพันธ์ขัดแย้ง

## การตรวจสอบข้อมูลและข้อผิดพลาด

ต้องมีเลขที่ ชื่อเรื่อง โรงพยาบาลอย่างน้อยหนึ่งแห่ง เครื่องมืออย่างน้อยหนึ่งรายการ และสมาชิกทีมอย่างน้อยหนึ่งคน วันที่สิ้นสุดต้องไม่ก่อนวันที่เริ่ม ตรวจ ID รายการซ้ำ และความเป็นเจ้าของเครื่องมือกับโรงพยาบาลจากฐานข้อมูล แสดงข้อผิดพลาดโดยคงค่าฟอร์มไว้ เมื่ออัปโหลด PDF ไม่สำเร็จให้ลองใหม่ได้โดยไม่สร้างคำสั่งซ้ำ

## การตรวจรับ

ทดสอบสร้างและแก้ไขด้วย admin และ technician และปฏิเสธการแก้ไขจาก role อื่น ทดสอบเลือกหลายโรงพยาบาล เครื่องมือชื่อซ้ำ ทีมหลายคน เลขที่คำสั่งซ้ำ และไฟล์ที่เกินขนาดหรือไม่ใช่ PDF ทดสอบเปิดและดาวน์โหลด PDF ตามสิทธิ์ ทดสอบเปลี่ยนคำสั่ง รีเฟรช และเข้าหน้าโดยตรง ไม่ให้ใช้โรงพยาบาลหรือเครื่องมือนอกคำสั่ง ตรวจว่าประวัติเดิมยังเปิดได้และหน้าจัดการเดิมยังใช้งานได้ ตรวจชนิดข้อมูลและ build พร้อมตรวจหน้าจอบนจอใหญ่และมือถือ
