# เครื่องมือมาตรฐานรายปีและ Check update ใบเซอร์ย้อนหลัง

สถานะ: ผู้ใช้ยืนยันให้แสดงรายการก่อนอัปเดต และคงเลขที่ใบเซอร์กับสถานะอนุมัติเดิม

## ผลลัพธ์ที่ผู้ใช้ต้องการ

- จัดการข้อมูล > เครื่องมือมาตรฐาน: แยกข้อมูลครบชุดเป็นรายปี พร้อม PDF ถ้ามี
- รายการสอบเทียบใหม่ใช้ข้อมูลปีล่าสุดของเครื่องมือที่เลือกเท่านั้น
- เมื่อแก้ข้อมูลปีเก่า มีปุ่ม Check update เพื่อตรวจและอัปเดตใบเซอร์ที่เคยใช้ข้อมูลนั้น
- การปรับ UC หลายรหัสและการเลือกในหน้ากรอกข้อมูลต้องยังทำงานตามเดิม

## ข้อเท็จจริงจากระบบปัจจุบัน

- `stdinstrumentrefs` เก็บรายละเอียดเครื่องมือชุดเดียว และโหลดด้วย generic Mongoose schema
- `StdInstrumentCert` แยก PDF ตาม instrumentRefId + year อยู่แล้ว หนึ่ง PDF ต่อเครื่องมือต่อปี
- `StdCalPointConfig` ผูกกับเครื่องมือ แต่ไม่มีปี
- `CalibrationRecord.std1` และ `uc1`–`uc6`/`ucT.std` เก็บสำเนาค่าเครื่องมือ ไม่มีรหัสรุ่นรายปี
- หน้าทั่วไปและ ISO ใช้ข้อมูลอ้างอิงจาก `/api/reference?type=stdinstruments`
- PDF ใบเซอร์ออกจาก `PdfViewer` ฝั่ง browser และเก็บลง `ArchivedCertificatePdf` ซึ่งปัจจุบันมีหนึ่งไฟล์ต่อ record
- `/api/certificates/[recordId]` ส่งไฟล์ที่ archive ไว้ จึงต้องปรับเส้นทางนี้ด้วยเพื่อไม่ให้แสดง PDF ก่อนแก้ไข

## แบบข้อมูลที่เสนอ

### เครื่องมือและข้อมูลรายปี

คง instrumentRefId เป็นตัวตนของเครื่องมือ ไม่เปลี่ยนเมื่อเพิ่มปีใหม่

เพิ่มเอกสารข้อมูลรายปี มี unique key `(instrumentRefId, year, revision)` ประกอบด้วย:

- ปีที่ผู้ใช้กำหนด แสดงเป็น พ.ศ. และแปลงเก็บด้วยรูปแบบเดียวทั้งระบบ
- รายละเอียดเครื่องมือครบชุด: รหัส ชื่อ ผู้ผลิต รุ่น serial certNo วันที่สอบเทียบ measurement unit correction expandedU และค่า uT ทุกตัว
- ตารางจุดสอบเทียบทุกตาราง รวมลำดับ pointValue unit และ stdValues
- การอ้างอิง PDF ของปีนั้น (อาจไม่มี)
- revision, ผู้แก้ไข และเวลาที่แก้ไข
- ประวัติรุ่นข้อมูลก่อนแก้ เพื่อให้ตรวจสอบผลต่างย้อนหลังได้

การเพิ่มปีใหม่ให้คัดลอกจากปีก่อนเป็นจุดตั้งต้นได้ แต่ผู้ใช้ต้องกดบันทึกปีใหม่อย่างชัดเจน การแก้ปีเก่าต้องไม่ทำให้ปีเก่ากลายเป็นปีล่าสุดเพียงเพราะ updatedAt ใหม่กว่า

### การผูกข้อมูลสอบเทียบ

เพิ่ม provenance ให้ข้อมูลเครื่องมือที่นำไปใช้ใน std1 และ UC ทุกช่อง:

- instrumentRefId
- referenceVersionId และ referenceYear
- referenceRevision
- รหัสตารางจุดสอบเทียบที่เลือกและรุ่นตาราง
- สำเนาค่ามาตรฐานที่นำไปใช้จริงในรายการนั้น

การเปิดรายการเดิมต้องไม่ดึงปีล่าสุดมาทับเอง การสร้างรายการใหม่หรือเลือกเครื่องมือใหม่จึงค่อยเลือกปีล่าสุด ข้อมูลที่บันทึกไว้ต้องอ่านได้แม้เครื่องมือหรือปีนั้นจะถูกแก้ไขภายหลัง

### ประวัติใบเซอร์

เก็บ PDF และ snapshot ของรายการก่อนปรับปรุงเป็น revision แยกจากไฟล์ปัจจุบัน พร้อมเหตุผลเครื่องมือ/ปีที่เปลี่ยน ผู้ทำรายการ และเวลา

ต้องป้องกันหน้า preview เก่าที่ยังเปิดอยู่ upload PDF รุ่นเก่ากลับมาทับรุ่นใหม่ โดยตรวจ record revision ตอน archive

## หน้าจอ

ภายในแถวเครื่องมือมาตรฐานที่กางออก:

1. ตัวเลือกปี เรียงใหม่ไปเก่า มีป้ายปีล่าสุด
2. ปุ่มเพิ่มปี พร้อมตัวเลือกคัดลอกข้อมูลจากปีที่มีอยู่
3. รายละเอียดและตารางจุดสอบเทียบของปีที่เลือก
4. PDF ของปีที่เลือก พร้อมอัปโหลด/เปิดไฟล์
5. ปุ่มบันทึกและ Check update
6. ผล Check update แสดงเลขที่ใบเซอร์ เครื่องมือลูกค้า โรงพยาบาล วันที่ และค่าอ้างอิงที่เปลี่ยน รวมรายการที่ต้องตรวจด้วยตนเอง
7. ผลการอัปเดตแสดงสำเร็จ/ล้มเหลวแยกแต่ละใบ และทำซ้ำเฉพาะรายการที่ยังไม่สำเร็จได้

## การตรวจผลกระทบและอัปเดต

- ค้นหาทุกรายการที่อ้างอิง instrumentRefId และ referenceYear เดียวกันและใช้ revision เก่า ทั้งระบบทั่วไปและ ISO
- ตรวจทุกตำแหน่ง std1, uc1–uc6 และ ucT ไม่เลือกจากปีของวันที่สอบเทียบเพียงอย่างเดียว
- คงค่าที่อ่านจากเครื่องลูกค้าและข้อมูลการวัดจริง
- แยกค่ามาตรฐานที่คำนวณมาจาก reference ออกจากค่าที่ผู้ใช้กรอกวัดเอง ก่อนปรับ correction หรือตาราง STD
- ถ้าพิสูจน์ที่มาของ STD readings เดิมไม่ได้ ให้แสดงรายการต้องตรวจ ไม่แทนค่าการวัดจริงโดยเดา
- คำนวณผลใหม่ด้วยสูตรเดิมของรายการ โดยใช้ข้อมูลอ้างอิงที่แก้ไข
- สร้าง PDF ใหม่ด้วย renderer เดียวกับหน้า preview รวมลายเซ็นตามนโยบายอนุมัติที่ผู้ใช้เลือก
- อัปเดต record และ PDF เป็นรุ่นเดียวกัน และป้องกันการแก้ซ้อนด้วย revision check
- งานจำนวนมากต้องประมวลผลเป็นชุดและทำต่อหลังข้อผิดพลาดได้ ไม่มีสถานะสำเร็จหาก PDF ใหม่ยังไม่สร้าง
- Check update ซ้ำโดยไม่มีการเปลี่ยนข้อมูลต้องไม่สร้างการแก้ไขซ้ำ

## ข้อมูลเดิม

- ไม่สามารถสร้างค่ามาตรฐานของปีก่อนจาก PDF metadata อย่างเดียวได้
- ข้อมูลเครื่องมือปัจจุบันจะนำไปตั้งต้นให้ปีที่ยืนยันแล้ว ส่วน PDF ที่มีหลายปีให้เชื่อมกับปีของตัวเอง
- รายการเก่าที่ไม่มี yearId ให้ตรวจรหัสเครื่องมือ + serial/certNo/วันที่มาตรฐานเพื่อหา version ที่แน่นอน
- กรณี match ได้หลายปีหรือขาดข้อมูลต้องแสดงให้ผู้ใช้ตรวจผูกปี ไม่ใช้ค่าปีล่าสุดแทนประวัติโดยอัตโนมัติ
- ต้องมี dry-run รายงานก่อนทำ migration จริง และคงข้อมูลเดิมสำหรับย้อนกลับ

## การทดสอบที่ต้องผ่าน

- เพิ่มปี แก้ปีเก่า คัดลอกปี และแนบ/เปลี่ยน PDF แยกปี
- ปี พ.ศ./ค.ศ. ถูก normalize ตรงกัน ไม่มีปีซ้ำต่างรูปแบบ
- รายการใหม่เลือกปีสูงสุด ไม่ใช่รุ่นที่แก้ล่าสุด
- รายการเดิมคงค่าปีเดิมเมื่อเปิดแก้ไข
- Check update พบครบทั้ง std1, UC ทุกช่อง และ ISO และไม่แตะเครื่องมือ/ปีอื่น
- legacy ที่ระบุปีไม่ได้ไม่ถูกอัปเดตโดยเดา
- การอัปเดตคง UUC readings, คำนวณ STD ที่มี provenance ได้ถูกต้อง และไม่ทับ STD ที่วัดจริง
- สร้าง PDF รุ่นใหม่จริง เก็บรุ่นก่อนหน้า และป้องกัน preview เก่าทับ revision ใหม่
- สิทธิ์ผู้ใช้ การแก้ซ้อน การกดซ้ำ ความล้มเหลวบางรายการ และการลองใหม่

## นโยบายที่ผู้ใช้ยืนยัน

- Check update แสดงรายการก่อนกดยืนยันอัปเดต
- ใบเซอร์ที่อนุมัติแล้วคงเลขที่และสถานะเดิม
